# 质量与交互约束

本文档是 Codex One-Click Skin 的发布门槛。主题可以改变视觉材料，但不能削弱 Codex 原生功能、可访问性或布局稳定性。

## 1. 固定框架

- QQ2007 模式标题栏高度为 `46px`。
- 全局工具栏高度为 `46px`，固定在标题栏下方。
- 状态栏高度为 `25px`，固定在窗口底部。
- 应用内容从 `y=92px` 开始，在状态栏上方结束。
- 原生任务页头高度保持 `46px`，必须与主内容左右边界对齐。
- 标题栏、工具栏、原生页头、主内容和状态栏不得相互覆盖。

## 2. 尺寸矩阵

每次发布至少验证以下桌面视口：

| 视口 | 目标 |
| --- | --- |
| `1438×600` | 宽屏低高度，验证输入框、状态栏和附件工具组 |
| `1282×720` | 标准窗口，验证完整侧栏和二级面板 |
| `960×720` | 中等宽度，验证内容收缩和标签滚动 |
| `720×800` | 窄屏，验证侧栏折叠、临时栏和控件保留 |

固定格式控件必须使用稳定高度、最小宽度、明确的 flex/grid 轨道或 `aspect-ratio`。文字变化、悬停、加载状态和图标变化不得改变相邻控件位置。

## 3. 原生交互

- 不得用截图、装饰层或复制按钮替代 Codex 原生控件。
- 装饰层必须使用 `pointer-events: none`。
- 可见按钮中心点必须由 `document.elementFromPoint()` 命中按钮本身或其子节点。
- 新对话、任务导航、项目、插件、摘要、附件、审阅、模型菜单、提交和恢复外观必须调用真实 Codex 行为。
- 输入框必须保持可编辑；空格、换行、附件和提交不得引起容器突然下跳。
- 侧栏展开、折叠、鼠标临时栏和再次展开必须形成完整闭环。

## 4. 二级控件

- 摘要栏、附件栏、审阅标签、文件预览和弹出菜单首次挂载时必须立即进入皮肤布局。
- 二级栏不得沿用官方窗口坐标而穿入自定义标题栏或工具栏。
- 附件标签仅允许在自己的滚动区水平滚动；活动标签不得被 `+`、展开或收回按钮覆盖。
- `+`、展开、收回、打开、缩放和选项菜单必须保持可见、可点击并具有完整边框。
- 右侧操作区保留固定宽度；标签数量增加时收缩标签滚动区，不压缩操作按钮。
- 二级面板关闭后不得残留白块、透明洞或不可点击的占位层。

## 5. 状态反馈

- `hover`、`:focus-visible`、`data-state="open"`、`aria-pressed="true"` 和选中状态必须有可辨识且一致的反馈。
- 同组按钮高度差不超过 `1px`，边框和内描边必须完整贴合。
- 悬停反馈不得改变按钮宽高或推动相邻内容。
- 临时侧栏应在原生触发后及时出现，且不得覆盖自定义顶栏或底部状态栏。
- 不得保留无语义的伪元素、蓝点、白边或调试标记。

## 6. 响应式与裁切

- 主内容、侧栏、输入框、标签栏和状态栏不得超出视口。
- 原生滚动条、消息快速定位条和右侧调整手柄必须保持可用。
- 低高度窗口优先减少装饰空间，不隐藏输入和任务操作。
- 窄屏可折叠侧栏，但顶部五个全局按钮的尺寸和位置不得随侧栏状态移动。
- 文本不得穿出按钮、覆盖图标或遮挡相邻控件；必要时使用省略和滚动，不按视口缩放字体。

## 7. 选择器与同步

- 优先使用稳定的 `data-*`、ARIA 语义和结构关系，避免依赖构建哈希类名。
- 对本地化 ARIA 名称同时兼容当前中文和英文形式。
- MutationObserver 必须识别路由、侧栏、摘要、附件标签和原生页头的新增、移除与状态变化。
- 同步函数必须幂等；重复注入不得增加重复按钮、监听器或装饰节点。
- Codex 更新造成选择器失效时应让验证失败，不得静默生成假控件补位。

## 8. 发布门槛

发布前必须运行：

```powershell
node --check .\assets\renderer-inject.js
node --check .\scripts\injector.mjs
node --check .\scripts\layout-check.mjs
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\run-tests.ps1
node .\scripts\injector.mjs --check-payload --theme-dir .\presets\preset-codex-1907-deep
node .\scripts\layout-check.mjs 9335
git diff --check
```

任何可见控件丢失、不可点击、被遮挡、尺寸偏差或测试违规都必须在发布前修复。
